PROJECT OVERVIEW
================================================================================
The Dark Store Optimizer (branded as "Zepto Optimizer") is a real-time inventory
management and vehicle routing optimization system designed for rapid delivery
networks. It combines demand prediction, inventory management, and route
optimization to prevent stockouts and optimize delivery operations across a
network of dark stores in Bangalore.

Core Problem: Minimize stockouts across distributed stores by predicting demand,
identifying critical inventory levels, and optimizing real-time routing of driver
vehicles to rebalance inventory.

Target Market: Last-mile rapid delivery platforms (e.g., Zepto, Blinkit)
Geographic Focus: Bangalore with 11 dark store locations

VERIFIED ALGORITHMS & MATHEMATICS
================================================================================

1. POISSON DISTRIBUTION (Demand Modeling)
   ✓ Order generation: np.random.poisson(λ/30) per tick
   ✓ Stockout probability: 1 - poisson.cdf(stock, λ)
   ✓ Implements: P(demand > stock) = P(X > stock) where X ~ Poisson(λ)
   ✓ Numerically stable (scipy implementation)

2. BERNOULLI TRIAL (Risk Assessment)
   ✓ Used in predictive_layer.py
   ✓ Binary risk evaluation: bernoulli.rvs(probability)
   ✓ Determines immediate risk with given probability

3. VEHICLE ROUTING PROBLEM (VRP-TW)
   ✓ OR-Tools RoutingIndexManager configured
   ✓ Multi-vehicle routing with time windows
   ✓ Capacity constraints enforced per vehicle
   ✓ Distance matrix: Euclidean * 10 (scaled to int)
   ✓ Transit callback properly registered
   ✓ Dimensions added for constraints

4. EUCLIDEAN DISTANCE CALCULATION
   ✓ Distance = sqrt((x1-x2)² + (y1-y2)²)
   ✓ Applied to lat/long coordinates (Bangalore)
   ✓ Scaled by 10 for integer representation

CONFIGURATION PARAMETERS
================================================================================

CRITICAL THRESHOLD (predictive_layer.py):
  Default: 0.80 (80% stockout probability)
  Effect: Nodes with >80% risk classified as SINK

SOURCE THRESHOLD (predictive_layer.py):
  Condition: stock > lambda_rate * 3 AND stockout_prob < 0.1
  Effect: Identifies overstocked nodes for redistribution

ORDER TICK INTERVAL (main.py):
  Lambda reduction: lambda_rate / 30.0
  Rationale: Scales hourly demand to 2-minute ticks (for 8-sec simulation)

ROUTE LIMITING (main.py):
  Limit: 3 sources and 3 sinks per product per tick
  Rationale: Prevents over-routing of vehicles

GHOST ROUTE GENERATION (main.py):
  Limit: 2 ghost routes per product
  Candidates: Nodes with 50-80% stockout probability

TRANSFER QUANTITY (main.py):
  Amount: 15 units per simulated delivery
  Constraint: Source max reduced by 15, sink receives 15

SIMULATION TICK (main.py):
  Interval: 8 seconds
  Rationale: Balance between responsiveness and computation
